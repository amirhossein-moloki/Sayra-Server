# ADR-009: Security Architecture

## Context
The SAYRA Central Backend runs in local, offline-first LAN gaming center environments. We need robust security boundaries, tamper resistance, and encrypted communications (TLS 1.3) without relying on public third-party Certificate Authorities.

## Decision
We implement a **Local PKI / Root CA** management model where the backend acts as a self-managed Certificate Authority to provision TLS 1.3 certificates, authenticated by **custom Token-Based handshakes** and secured with an **immutable append-only Hash-Chained Audit Trail**.

## Alternatives Considered
1. **Public Certificates (Let's Encrypt)**: Infeasible because local LAN networks often run completely offline or behind strict firewalls without public domain names.
2. **Plaintext / Unencrypted LAN**: Unacceptable for enterprise applications; allows sniffing of billing credentials, session data, and administrator commands on shared LAN networks.

## Reasons
* Actively protects against local LAN sniffing, session hijacking, and man-in-the-middle (MITM) attacks.
* Autonomously provisions server certificates and registers trusted clients without internet dependencies.
* Hash-chained audit logs ensure security administrators can immediately detect database tamper or log modification attempts.

## Consequences
* Upon first boot, the backend automatically generates a Local Root CA.
* Client workstations must install this Root CA in their certificate store during initial setup.
* Security audits require auditing the cryptographic integrity of the SQL `AuditLog` table hash-chains.

## Risks
* Private Root CA key leakage would compromise the entire local network security (mitigated by storing the private key encrypted with machine-specific credentials or a HSM/TPM API where available).
* Expired certificates could cause local LAN communication dropouts (mitigated by implementing automated renewal background workers).

## Migration/Evolution Strategy
If the network environment shifts to a fully online, SaaS-based model, the backend can seamlessly disable its internal PKI generator and switch to standard ACME (Let's Encrypt) or public cloud certificate managers.
