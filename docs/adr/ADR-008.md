# ADR-008: Communication Architecture

## Context
The Central Backend must concurrently host and orchestrate three distinct protocols:
1. **UDP**: High-frequency server discovery on local networks (Port 37020).
2. **TCP**: Secure, persistent TLS 1.3 tunnels for heartbeats, commands, and telemetry (Port 37021).
3. **HTTPS / REST**: Admin control, client authentication, and file updates (Port 443).

## Decision
We implement all three communication layers as separate listeners inside the unified **ASP.NET Core Monolith host process**, communicating with the application core via a shared **In-Memory EventBus / Command Dispatcher**.

## Alternatives Considered
1. **Separate Processes**: Running a dedicated TCP service, a dedicated UDP discovery service, and a REST service. This increases deployment and orchestration complexity for local LAN centers.
2. **Third-Party TCP Gateway**: Using an external broker (like MQTT or RabbitMQ) to terminate client connections, translating them to HTTP for the backend. Highly complex and forces client protocol modifications, violating our core client-side immutability constraint.

## Reasons
* **Single Deployment Artifact**: Simplifies management. One container or process manages the entire local network surface.
* **Unified State**: Direct, low-latency communication between the custom TCP connection manager and the core memory bus.
* **In-Memory Event Bus**: Decouples network layers from core domain logic. A physical TCP connection handler parses incoming packets and merely dispatches a `TelemetryReceivedEvent` onto the bus. The Core Domain doesn't care that the event originated from a TCP socket.

## Consequences
* The monolith process will open ports 37020 (UDP), 37021 (TCP), and 5001/443 (HTTPS) simultaneously.
* The TCP listener will use custom .NET Sockets and `System.IO.Pipelines` to parse packets without memory allocations, terminating TLS 1.3 using `SslStream`.

## Risks
* High-volume network traffic on one protocol (e.g., massive UDP storms) could degrade performance on REST APIs (mitigated by configuring threadpool limits and isolation).
* A crash in the TCP layer could restart the REST API (mitigated by robust try-catch handlers in socket loops).

## Migration/Evolution Strategy
Because network gateways are decoupled from the domain by the EventBus, we can easily split the TCP Server into an independent process ("TCP Gateway Service") in the future without changing a single line of business or billing domain code.
