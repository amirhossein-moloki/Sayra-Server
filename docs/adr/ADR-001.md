# ADR-001: Language and Runtime

## Context
The Central Backend must handle high-throughput, low-latency, and concurrent real-time LAN communication protocols (UDP Server Discovery, persistent TLS 1.3 TCP tunnels) alongside high-fidelity business operations (financial billing, session management, auditing).

## Decision
We select **C# on .NET 8.0 (LTS)** as the primary programming language and runtime environment.

## Alternatives Considered
1. **Go (Golang)**: Outstanding socket network performance and light footprint, but building complex billing and domain logic in Go leads to excessive boilerplate.
2. **Node.js (TypeScript)**: Great ecosystem and quick iteration, but lacks robust multi-threaded performance and native socket primitives required for thousands of secure persistent TCP connections under load.
3. **Rust**: Excellent safety and performance, but the high learning curve and borrow-checker complexity drastically slow down business logic changes.

## Reasons
* Modern language features (Pattern matching, records, async/await, compile-time LINQ) enable highly expressive, type-safe business domain modeling.
* Industry-leading async socket capabilities (`System.Net.Sockets`, `System.IO.Pipelines`) and native TLS 1.3 `SslStream` support out of the box.
* Excellent open-source integration libraries (Npgsql for PostgreSQL, StackExchange.Redis).
* Broad developer availability and robust ecosystem tools.

## Consequences
* The entire backend codebase will reside in a structured .NET Solution (`.sln`) with strong-typed projects.
* Development requires .NET 8 SDK and IDE support (VS Code, JetBrains Rider, or Visual Studio).

## Risks
* Higher initial memory footprint compared to Go or Rust (though highly optimized in .NET 8).
* Must manage garbage collection characteristics under extremely high TCP allocations (mitigated via `ArrayPool` and Pipelines).

## Migration/Evolution Strategy
Our modules are strictly bounded. Should a specific module (e.g., Telemetry ingestion) eventually demand a native Go/Rust runtime for cost-efficiency, the modular monolith design ensures it can be extracted cleanly.
